# NeoOS Universal — 통합 프로젝트

NeoOS Universal은 지금까지 만든 프로젝트를 한 방향으로 연결하는 통합 진입점입니다. 기존 소스와 데이터는 삭제하거나 덮어쓰지 않고, 별도 디렉터리 `neoos-universal/`에서 개발합니다.

## 통합 대상

- **NeoOS-2** — 기존 NeoOS 재구축 스타터, 작업 큐/MCP 상태 도구, GitHub Actions heartbeat, 기존 문서와 Android launcher를 보존합니다.
- **YangVM** — [브라우저 CPU 에뮬레이터 및 실험실](https://github.com/gw140427-rgb/Repository-YangVM-Description-A-simple-virtual-machine-project-built-on-Android-Visibility-Public). 현재는 교육용 8비트 CPU이며 PC 운영체제를 실행하는 VM은 아닙니다.
- **NeoOS PC Edition** — 저사양/구형 PC를 위한 LFS 기반 OS 방향. 기존에 언급된 ISO 빌드 결과는 실제 부팅 검증 전까지 완성된 OS로 표시하지 않습니다.
- **Universal Boot + VM 계획** — 실제 PC 멀티부팅과 가상 머신을 하나의 관리 화면에서 다루는 장기 목표입니다.

## 지금 들어 있는 기능

`index.html`은 정적 웹 대시보드입니다. OS별 실행 방식, 호환성 구분, 준비 항목을 보여주고 기존 프로젝트로 연결합니다. 설치 버튼은 OS를 실제로 설치하지 않으며, 체크리스트/계획 화면을 의미합니다.

## 실제 구현과 아직 계획인 기능

| 기능 | 현재 상태 |
|---|---|
| 통합 대시보드 및 프로젝트 링크 | 구현 |
| OS 호환성/실행 방식 구분 | 구현(설명 데이터) |
| YangVM 기존 프로젝트 연결 | 구현 |
| NeoOS-2 기존 작업/MCP 프로젝트 연결 | 링크/문서 통합 |
| 실제 UEFI 멀티부팅 로더 | 미구현 |
| QEMU 기반 실제 VM 실행 | 미구현 |
| Windows 1.0–11 전체 자동 설치 | 미구현·보장 불가 |
| Linux 설치 이미지 자동 다운로드/검증 | 미구현 |
| NeoOS PC Edition ISO의 실제 부팅 테스트 | 별도 빌드 및 실기기 테스트 필요 |

## 개발 원칙

1. **데이터 보존 우선:** 기존 파일, 작업 데이터, Docker/서비스 볼륨은 건드리지 않습니다.
2. **검증 표시:** 구현됨, 빌드됨, 실행 테스트됨, 실제 기기에서 부팅됨을 서로 다른 상태로 취급합니다.
3. **실제 멀티부팅과 VM을 구분:** UEFI/GRUB는 설치된 OS 또는 지원되는 부팅 이미지를 시작하고, QEMU 같은 VM 엔진은 게스트 OS를 가상 하드웨어에서 실행합니다. 둘을 관리 화면에서 통합하되 기술적으로 같은 기능인 것처럼 표시하지 않습니다.
4. **레거시 Windows:** Windows 1.x–3.x는 DOS 기반 실행 환경이 필요합니다. 최신 Windows 설치와 같은 경로로 처리하지 않고 별도 DOS/에뮬레이션 경로로 계획합니다.
5. **라이선스와 출처:** 사용자가 권한이 있는 설치 이미지만 사용합니다. 독점 OS 이미지를 임의로 미러링하거나 무단 배포하지 않습니다.
6. **비용:** 초기 웹 대시보드는 정적 호스팅을 목표로 하며 유료 API나 카드 등록을 요구하지 않습니다. 실제 VM을 서버에서 실행하는 기능은 무료 호스팅이 보장하지 않습니다.

## 로컬 실행

아무 빌드 도구 없이 `neoos-universal/index.html`을 브라우저에서 열 수 있습니다. GitHub Pages에 게시하려면 저장소 Pages 설정에서 이 경로를 사이트 루트로 직접 지정할 수 없으므로, 필요하면 별도 Pages 워크플로를 추가해야 합니다.
